# Instalación de LXD

> **⚠️ DOCUMENTO PARCIALMENTE HISTÓRICO** — Este archivo describe la creación inicial de contenedores (k8s-master-1 en D1, k8s-worker-1 en D2) y no refleja la reubicación posterior: k8s-worker-1 fue movido a D1 (192.168.1.31) y se creó k8s-worker-2 en D2 (192.168.1.32). Tampoco menciona el workaround de snapd en DV0 (394 MiB RAM). Para el estado actual, consultar [README-TECH.md — Fase 2.3](./README-TECH.md#fase-23--cluster-lxd) y [Fase 13](./README-TECH.md#fase-13--resiliencia-y-alta-disponibilidad).

## Paso 1: Instalar LXD

El paquete lxd no está en los repositorios estándar. Necesitamos instalarlo vía snap:

```bash
sudo snap install lxd
```

## Paso 2: Inicializar LXD

Lanzamos el asistente:

```bash
lxd init
```

### Respuestas recomendadas para el asistente lxd init:

**Would you like to use LXD clustering? (yes/no) [default=no]: no**

Responder `no` evita complejidad innecesaria.

**Do you want to configure a new storage pool? (yes/no) [default=yes]: yes**

Disponemos de 133.4 GB sin formato en el disco NVMe M.2 (nvme0n1p4).

**Name of the new storage pool [default=default]: default**

Usar el nombre por defecto.

**Name of the storage backend to use (dir, lvm, powerflex, zfs, btrfs, pure, ceph) [default=zfs]: zfs**

ZFS es el backend recomendado por su alto rendimiento en discos NVMe.

**Create a new ZFS pool? (yes/no) [default=yes]: yes**

LXD creará el pool utilizando ZFS.

**Would you like to use an existing empty block device (e.g. a disk or partition)? (yes/no) [default=no]: yes**

Disponemos de la partición nvme0n1p4 sin formatear.

**Path to the existing block device: /dev/nvme0n1p4**

Esta partición está reservada para ZFS.

**Would you like to connect to a MAAS server? (yes/no) [default=no]: no**

MAAS no se utiliza.

**Would you like to create a new local network bridge? (yes/no) [default=yes]: yes**

Crear el bridge lxdbr0.

**What should the new bridge be called? [default=lxdbr0]: lxdbr0**

Convención estándar.

**What IPv4 address should be used? (CIDR subnet notation, "auto" or "none") [default=auto]: auto**

Usar la configuración automática de LXD para el bridge (rango privado 10.x.x.x).

**What IPv6 address should be used? (CIDR subnet notation, "auto" or "none") [default=auto]: none**

IPv4 es suficiente.

**Would you like the LXD server to be available over the network? (yes/no) [default=no]: yes**

Necesario para gestionar ambos nodos (D1 y D2) de forma centralizada.

**Address to bind LXD to (not including port) [default=all]: [default=all]**

Permite que LXD escuche en todas las interfaces.

**Port to bind LXD to [default=8443]: 8443**

Puerto estándar.

**Would you like stale cached images to be updated automatically? (yes/no) [default=yes]: yes**

Mantener imágenes actualizadas automáticamente.

**Would you like a YAML "lxd init" preseed to be printed? (yes/no) [default=no]: yes**

Imprimir la configuración en YAML para replicarla en D2.

### Archivo de configuración generado (lxd-config.yaml):

Guardar la salida YAML del asistente como `lxd-config.yaml` en `~/D-Lab/files/`.

## Paso 3: Instalar LXD en D2 y replicar configuración

En el nodo D2, instalar LXD:

```bash
sudo snap install lxd
```

Copiar el archivo `lxd-config.yaml` desde D1:

```bash
scp -P 9622 elarreglador@D1:/home/elarreglador/D-Lab/files/lxd-config.yaml ./lxd-config.yaml
```

Aplicar la configuración:

```bash
sudo lxd init --preseed < lxd-config.yaml
```

## Paso 4: Crear red macvlan en D1 y D2

Para que los contenedores obtengan IPs directamente de la red física (192.168.1.0/24), necesitamos crear una red macvlan sobre `enp2s0`.

En **D1**, ejecutar:

```bash
lxc network create macvlan0 --type=macvlan parent=enp2s0
```

En **D2**, ejecutar el mismo comando:

```bash
lxc network create macvlan0 --type=macvlan parent=enp2s0
```

Verificar que la red se creó correctamente:

```bash
lxc network list
```

Debe mostrar `macvlan0` en ambos nodos.

## Paso 5: Crear perfil personalizado para contenedores Kubernetes

En **D1**, crear un perfil que use macvlan:

```bash
lxc profile create k8s
```

Editar el perfil:

```bash
lxc profile edit k8s
```

Reemplazar el contenido con:

```yaml
config: {}
description: "Perfil para contenedores Kubernetes con macvlan"
devices:
  eth0:
    name: eth0
    network: macvlan0
    type: nic
  root:
    path: /
    pool: default
    type: disk
name: k8s
```

Guardar y salir (Ctrl+X en nano).

Copiar este perfil a **D2**. Una opción es exportar el perfil:

```bash
lxc profile show k8s > k8s-profile.yaml
```

Copiar el archivo a D2:

```bash
scp -P 9622 k8s-profile.yaml D2:~/k8s-profile.yaml
```

En **D2**, importar el perfil:

```bash
lxc profile create k8s
lxc profile edit k8s < ~/k8s-profile.yaml
```

## Paso 6: Crear contenedor k8s-master-1 en D1 con perfil macvlan

Crear el contenedor con el perfil `k8s`:

```bash
lxc launch ubuntu:22.04 k8s-master-1 --profile k8s
```

Verificar que está creado:

```bash
lxc list
```

## Paso 7: Configurar IP estática 192.168.1.21 en k8s-master-1

Acceder al contenedor:

```bash
lxc exec k8s-master-1 -- bash
```

Dentro del contenedor, crear/editar la configuración de red:

```bash
sudo nano /etc/netplan/01-k8s.yaml
```

Agregar la siguiente configuración:

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      dhcp4: no
      addresses:
        - 192.168.1.21/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses:
          - 8.8.8.8
          - 8.8.4.4
```

Aplicar permisos y la configuración:

```bash
chmod 600 /etc/netplan/01-k8s.yaml 
sudo netplan apply
```

Verificar la IP asignada:

```bash
ip addr show eth0
```

Debe mostrar solo `192.168.1.21/24`, sin la IP adicional del DHCP.

Salir del contenedor:

```bash
exit
```

## Paso 10: Validar conectividad entre contenedores

Desde **D1**, hacer ping a k8s-worker-1:

```bash
lxc exec k8s-master-1 -- ping -c 3 192.168.1.22
```

Desde **D2**, hacer ping a k8s-master-1:

```bash
lxc exec k8s-worker-1 -- ping -c 3 192.168.1.21
```

Ambos pings deben funcionar correctamente ahora. Los contenedores están conectados directamente a la red física a través de macvlan.

```bash
lxc exec k8s-worker-1 -- bash -c "apt update && apt upgrade -y && apt install -y curl wget gnupg2 apt-transport-https ca-certificates"
```
