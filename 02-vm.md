# Instalación de LXD

## Paso 1: Instalar LXD

El paquete lxd no está en los repositorios estándar. Necesitamos instalarlo vía snap:

```bash
sudo snap install lxd
```

## Paso 2: Inicializar LXD

Lanzamos el asistente:

```bash
lxd init
```

### Respuestas recomendadas para el asistente lxd init:

**Would you like to use LXD clustering? (yes/no) [default=no]: no**

Debemos responder `no` a la pregunta de clustering únicamente si el objetivo fuera crear una base de datos distribuida y alta disponibilidad para el propio servicio LXD.

Esto es necesario solo en los siguientes casos:

- Administración unificada y transparente: Si se desea que LXD gestione automáticamente la colocación de contenedores entre nodos basándose en políticas de recursos.
- Alta Disponibilidad (HA): Si requiere que, en caso de que un nodo falle, los contenedores LXC se reinicien automáticamente en el nodo superviviente.
- Almacenamiento y Red compartidos: Si hay una infraestructura de red (como OVN) y almacenamiento distribuido (como Ceph).

Para D-Lab, responder "no" evita complejidad innecesaria que interferiría con el despliegue de Kubernetes.

**Do you want to configure a new storage pool? (yes/no) [default=yes]: yes**

Disponemos de 133.4 GB sin formato en el disco NVMe M.2 (nvme0n1p4). El asistente nos permitirá aprovechar este espacio.

**Name of the new storage pool [default=default]: default**

Usar el nombre por defecto, ya que es el estándar y facilitará la gestión futura.

**Name of the storage backend to use (dir, lvm, powerflex, zfs, btrfs, pure, ceph) [default=zfs]: zfs**

ZFS es el backend recomendado por su alto rendimiento en discos NVMe, facilitando snapshots y clones para optimizar la gestión de contenedores.

**Create a new ZFS pool? (yes/no) [default=yes]: yes**

LXD creará el pool utilizando ZFS sobre el espacio disponible en el disco NVMe.

**Would you like to use an existing empty block device (e.g. a disk or partition)? (yes/no) [default=no]: yes**

Disponemos de un espacio sin formatear específicamente reservado (nvme0n1p4). Seleccionar esta opción permite asignarlo exclusivamente a ZFS.

**Path to the existing block device: /dev/nvme0n1p4**

Esta partición corresponde al espacio reservado en el disco NVMe M.2.

**Would you like to connect to a MAAS server? (yes/no) [default=no]: no**

MAAS no se utiliza en este entorno.

**Would you like to create a new local network bridge? (yes/no) [default=yes]: yes**

La creación de un puente de red es necesaria para que los contenedores obtengan conectividad y se comuniquen entre sí y con el exterior.

**What should the new bridge be called? [default=lxdbr0]: lxdbr0**

Es la convención estándar en LXD.

**What IPv4 address should be used? (CIDR subnet notation, "auto" or "none") [default=auto]: 192.168.1.1/24**

**IMPORTANTE**: Usar `192.168.1.1/24` para unificar la red de contenedores con la red física del laboratorio (192.168.1.0/24). Esto permite asignar IPs estáticas a los contenedores en el rango 192.168.1.0/24.

**What IPv6 address should be used? (CIDR subnet notation, "auto" or "none") [default=auto]: none**

La gestión de red con IPv4 es suficiente.

**Would you like the LXD server to be available over the network? (yes/no) [default=no]: yes**

Necesario para gestionar ambos nodos (D1 y D2) de forma centralizada y que se comuniquen a través de la API de LXD.

**Address to bind LXD to (not including port) [default=all]: [default=all]**

Permite que el servicio LXD escuche en todas las interfaces de red disponibles.

**Port to bind LXD to [default=8443]: 8443**

Puerto estándar para las comunicaciones remotas de LXD.

**Would you like stale cached images to be updated automatically? (yes/no) [default=yes]: yes**

Permite que LXD mantenga sus imágenes base actualizadas automáticamente.

**Would you like a YAML "lxd init" preseed to be printed? (yes/no) [default=no]: yes**

Imprime un archivo YAML con toda la configuración. Esto es útil para replicar exactamente la misma configuración en D2.

### Archivo de configuración generado (lxd-config.yaml):

```yaml
config:
  core.https_address: '[::]:8443'
networks:
- config:
    ipv4.address: 192.168.1.1/24
    ipv6.address: none
  description: ""
  name: lxdbr0
  type: ""
  project: default
storage_pools:
- config:
    source: /dev/nvme0n1p4
  description: ""
  name: default
  driver: zfs
storage_volumes: []
profiles:
- config: {}
  description: ""
  devices:
    eth0:
      name: eth0
      network: lxdbr0
      type: nic
    root:
      path: /
      pool: default
      type: disk
  name: default
projects: []
cluster: null
```

Guardar esta salida como `lxd-config.yaml`.

## Paso 3: Instalar LXD en D2 y replicar configuración

En el nodo D2, instalar LXD:

```bash
sudo snap install lxd
```

Copiar el archivo `lxd-config.yaml` desde D1:

```bash
scp -P 9622 elarreglador@D1:/home/elarreglador/D-Lab/files/lxd-config.yaml ./lxd-config.yaml
```

Aplicar la configuración:

```bash
sudo lxd init --preseed < lxd-config.yaml
```

## Paso 4: Verificar instalación y configuración de red

En ambos nodos (D1 y D2), verificar que LXD está funcionando:

```bash
lxc network list
```

Debe mostrar el bridge `lxdbr0` con la dirección `192.168.1.1/24`.

## Paso 5: Crear contenedor k8s-master en D1

Crear el contenedor con Ubuntu 22.04 LTS:

```bash
lxc launch ubuntu:22.04 k8s-master
```

Esperar a que el contenedor esté listo:

```bash
lxc list
```

Debe mostrar el contenedor `k8s-master` en estado `RUNNING`.

## Paso 6: Configurar IP estática 192.168.1.21 para k8s-master

Acceder al contenedor:

```bash
lxc exec k8s-master -- bash
```

Crear/editar el archivo de configuración de red con netplan:

```bash
sudo nano /etc/netplan/01-lxd.yaml
```

Agregar la siguiente configuración:

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      dhcp4: no
      addresses:
        - 192.168.1.21/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses:
          - 8.8.8.8
          - 8.8.4.4
```

Aplicar la configuración:

```bash
sudo netplan apply
```

Verificar la IP asignada:

```bash
ip addr show eth0
```

Salir del contenedor:

```bash
exit
```

## Paso 9: Validar conectividad entre contenedores

Desde D1, hacer ping a k8s-worker (192.168.1.22):

```bash
lxc exec k8s-master -- ping -c 3 192.168.1.22
```

Desde D2, hacer ping a k8s-master (192.168.1.21):

```bash
lxc exec k8s-worker -- ping -c 3 192.168.1.21
```

## Paso 10: Instalar dependencias base en ambos contenedores

En ambos contenedores, ejecutar:

```bash
lxc exec k8s-master -- bash -c "apt update && apt upgrade -y && apt install -y curl wget gnupg2 apt-transport-https ca-certificates"
lxc exec k8s-worker -- bash -c "apt update && apt upgrade -y && apt install -y curl wget gnupg2 apt-transport-https ca-certificates"
```
